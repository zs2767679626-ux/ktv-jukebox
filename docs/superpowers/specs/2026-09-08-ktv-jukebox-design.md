# 办公室 KTV 点歌台 · 设计文档

日期：2026-09-08
状态：已与用户逐节确认

## 1. 背景与目标

为公司员工做一个共享的 KTV 风格点歌台。员工在任何设备打开网页即可点歌、切歌、调音量；音乐由公司一台连接蓝牙音箱的电脑实际播放，全员共享收听。核心理念是"权力下放"：人人平等、完全匿名，任何控制操作都不留身份痕迹。

MVP 先行：先跑起来，后续按使用反馈迭代。

## 2. 需求清单

| 编号 | 需求 |
|---|---|
| R1 | 全员共享点歌，KTV 点歌台风格界面 |
| R2 | 歌源走网易云等音乐平台 API |
| R3 | 完全匿名、全员平等：点歌/切歌/暂停/音量人人可控制，不登录、不显示点歌人 |
| R4 | 声音从公司电脑连的蓝牙音箱播出 |
| R5 | 播放端跨平台（Windows / Mac 同一份程序），换电脑登录即可，不绑死机器 |
| R6 | 界面五大模块：播放区（歌词/进度/下一首预告）、点歌区（搜索/分类/拼音索引/榜单）、已点歌单（置顶/删除）、全员控制条（含音量调节/静音）、扫码点歌 |
| R7 | 云端部署：账号/网页/数据在云服务器，任何地方可访问 |
| R8 | 界面自适应：手机三标签页布局，电脑/大屏三栏布局 |

## 3. 总体架构

```
┌─────────────────────────────────────────────┐
│  云服务器（腾讯 CloudStudio 免费版）          │
│  ┌─────────────┐   ┌──────────────────────┐ │
│  │ 点歌台后端   │   │ 网易云 API 服务        │ │
│  │ Node.js +   │──▶│ (NeteaseCloudMusicApi)│ │
│  │ Express + WS │   │ 搜索/歌曲地址/歌词     │ │
│  │ + SQLite    │   └──────────────────────┘ │
│  └──────┬──────┘                            │
└─────────┼───────────────────────────────────┘
          │ WebSocket（实时双向）
   ┌──────┴───────────────┐
   │                      │
员工手机/电脑          公司电脑播放端
浏览器打开网页         Python + mpv
（Win/Mac/手机都行）     → 蓝牙音箱 📢
点歌/切歌/调音量        开机自启、自动连云端
```

### 部件职责

| 部件 | 技术 | 职责 |
|---|---|---|
| 点歌台后端 | Node.js + Express + ws + SQLite | 网页托管、点歌队列、全员控制指令中转、历史记录、实时状态广播 |
| 音乐源服务 | NeteaseCloudMusicApi（开源项目，与后端同机部署，仅内网访问） | 搜索歌曲、拿播放地址、拿歌词 |
| 网页前端 | 原生 HTML/CSS/JS，零构建 | 五大模块界面 + 二维码 + WebSocket 连接 |
| 播放客户端 | Python + mpv（跨平台） | 连云端领任务：播放/暂停/切歌/调音量，输出到蓝牙音箱 |

### 关键决定

1. **WebSocket 实时通信**：点歌、切歌、音量即时生效，所有页面 1 秒内同步（不做轮询）。
2. **点歌队列存内存**（重启清空），**历史记录存 SQLite**（持久保留）。
3. **部署在腾讯 CloudStudio 免费版**，代码结构保留迁移余地，以后可搬正式服务器。
4. **播放端登录制**：首次运行输入设备口令绑定云端，换电脑重装即可（口令仅用于播放设备与云端配对，与员工身份无关，不记录任何点歌人信息）。

## 4. 界面布局

### 手机（主要点歌设备）：底部三标签

- **点歌页**：顶部搜索框（歌名/歌手/首字母均可搜）+ 分类入口宫格：歌手、语种、风格、拼音 A–Z 索引、热门榜、新歌榜
- **播放页**：当前歌曲大字 + 滚动歌词 + 进度条 + 下一首预告 + 控制条（播放/暂停、切歌、音量滑条、静音）
- **已点页**：排队列表，每首可 ⏫ 置顶、🗑 删除

### 电脑/大屏：三栏布局

- 左栏：当前播放 + 歌词 + 控制条 + 二维码
- 中栏：分类/搜索区、选歌结果
- 右栏：已点歌单（置顶/删除）

## 5. 交互规则

1. **点歌排队，不打断**：新歌进队列末尾，当前歌播完接着播（KTV 逻辑，区别于参考原版的"点歌直接打断"）。
2. **置顶** = 插到"下一首"播放位。
3. **切歌** = 跳过当前，立刻播下一首；队列空则停止。
4. **全员控制实时同步**：任何人调节音量/切歌，所有在线页面 1 秒内同步显示。
5. **匿名**：界面不显示任何点歌人信息，无登录。
6. **VIP/付费歌**：搜索列表打标签；可播则播，版权受限自动跳过并在历史注明原因。
7. 播放页显示**二维码**，扫码直达点歌页。

## 6. 技术实现要点

### 音量（核心需求）

- 播放端以 mpv 播放，音量调的是 **mpv 自身音量（0–100）**，不动系统音量。
- 流程：前端滑条/按钮 → WebSocket 指令 → 服务器记录当前音量 → mpv 生效 → 广播给所有页面同步。
- 静音：点一下静音（记住原音量），再点恢复。
- 播放端断线重连后自动恢复上次音量。

### 歌词

- 后端从网易云取 LRC 歌词，前端解析并按播放进度高亮当前句、自动滚动。
- 歌词时钟以服务器时间戳校准，误差控制在 1 秒内。
- 无歌词时显示"纯音乐/暂无歌词"。

### 音乐源

- NeteaseCloudMusicApi 与后端同机部署，仅内网调用，不暴露公网。
- 搜索返回 fee 字段，前端标记 VIP/付费标签。
- 播放地址由后端获取后交给播放端；VIP 无权限时队列自动跳到下一首，历史记录 reason。

### 异常处理

| 情况 | 表现 |
|---|---|
| 播放端电脑关机 | 网页顶部显示"播放端离线"，点歌照常排队，重连自动接着播 |
| 蓝牙音箱掉线 | 播放端暂停并上报，网页提示 |
| 网易云 API 故障 | 搜索提示"暂时不可用"，已点歌单不受影响 |
| 网页断线重连 | 自动重连（指数退避），重连后同步最新状态 |
| 服务器重启 | 队列清空（内存）、历史保留（SQLite） |

## 7. 测试方式

1. 开发期：本地起全套服务，播放端**虚拟模式**（不出声、打日志）测通点歌/切歌/音量/歌词全流程。
2. 部署后：真实歌曲实测点歌、切歌、音量同步。
3. 验收：公司电脑连蓝牙音箱，员工手机扫码实测。

```
  player/    # Python 播放客户端（Win/Mac 通用）

```

## 9. 范围边界（MVP 不做的）

- 不做登录/身份/昵称（需求 R3 明确排除）
- 不做歌曲收藏、个人歌单、评论等个性化功能
- 不做音频流中转（方案 C 已排除）
- 不做外网穿透（若未来有需要再加）
